# מערכת הכללים — HebrewCalendar

כללים אלה מחייבים כל מי שנוגע בקוד: הסוכן הראשי וכל סוכן-משנה.
סוכן-משנה מקבל תמיד בפרומפט שלו הפניה לקובץ הזה וחייב לקרוא אותו לפני עבודה.

## 1. משמעת תוכנית (אין סטייה)
1. התוכנית המחייבת היא `docs/ARCHITECTURE.md`; השלב הנוכחי מוגדר ב-`docs/PROGRESS.md`.
2. אסור לממש פיצ'ר שאינו בשלב הנוכחי. רעיון טוב באמצע עבודה → נרשם ב-`docs/WISHLIST.md` וממשיכים.
3. שינוי בתוכנית מחייב אישור מפורש מהמשתמש, ולאחריו עדכון `ARCHITECTURE.md` + שורת תיעוד ב-`PROGRESS.md`.
4. סוכן-משנה שמזהה בעיה בתוכנית עוצר ומדווח למפקח — לא מאלתר.

## 2. כלל 500 השורות (כלל ראשי)
- אף קובץ קוד לא יעלה על **500 שורות** (כולל הערות, לא כולל קבצי lock/generated).
- קובץ שמתקרב ל-450 שורות מתוכנן לפיצול; קובץ שעבר 500 — מפוצל באותו commit.
- פיצול לפי אחריות: widget נפרד, service נפרד, extension נפרד — לא "חלק א'/חלק ב'".

## 3. מבנה ותיעוד
1. כל קובץ חדש/שנמחק/ששינה תפקיד מעודכן ב-`docs/INDEX.md` באותו commit.
2. בסיום כל שלב או סשן עבודה מעדכנים את `docs/PROGRESS.md`: מה נעשה, מה נותר, החלטות שהתקבלו.
3. לאחר משימה מורכבת (באג קשה, אינטגרציה חדשה, החלטה ארכיטקטונית) נרשם לקח ב-`docs/LESSONS.md` — בדוק שם לקחים רלוונטיים **לפני** משימה דומה.
4. שמות קוד, מזהים והערות בקוד — באנגלית. טקסטים למשתמש — בעברית דרך שכבת strings (ARB), לא מחרוזות קשיחות ב-UI.

## 4. טיפוגרפיה וריספונסיביות
1. **גודל בסיס אחד** מוגדר ב-`lib/core/theme/dimens.dart` (ברירת מחדל 16). כל גודל טקסט אחר מוגדר **כמכפלה יחסית** שלו (המקבילה של rem). אסור גודל טקסט מספרי קשיח בשום widget.
2. מכבדים את `MediaQuery.textScaler` — האפליקציה לא נשברת בהגדלת גופן של המערכת.
3. פריסות עם `LayoutBuilder`/`MediaQuery` ויחידות יחסיות; אין רוחב/גובה קשיח למסכים מלאים. נקודות שבירה מרוכזות ב-`dimens.dart`.
4. RTL מלא: משתמשים ב-`start`/`end` (לא `left`/`right`) בכל padding/alignment.

## 5. אבטחה ובידוד משתמשים
1. אימות אך ורק עם Google Sign-In דרך Firebase Auth.
2. כל מסמך ב-Firestore שייך למשתמש/ליומן; ה-Security Rules מאמתות `request.auth.uid` על כל קריאה וכתיבה. **אסור** rule פתוח (`allow read, write: if true`) גם לא "זמנית".
3. משתתפים באירוע ניגשים רק לאירועים ששותפו איתם במפורש (רשימת `participantUids` בבדיקת ה-rules).
4. אין סודות בריפו: מפתחות/`google-services.json` ב-gitignore; תבנית דוגמה בלבד נשמרת בריפו.
5. קלט משתמש עובר ולידציה בצד לקוח **וגם** נאכף ב-Security Rules (טיפוסים, אורכים, שדות מותרים).
6. קבצים מצורפים נשמרים ב-Storage תחת נתיב המשתמש, עם rules תואמות ומגבלת גודל.

## 6. זיכרון ומשאבים
1. כל `StreamSubscription`, `AnimationController`, `TextEditingController`, `FocusNode`, listener — מבוטל/מנוקה ב-`dispose`.
2. האזנות Firestore ממוקדות (query מצומצם), נסגרות כשהמסך יורד; אין האזנה גלובלית לכל האוסף.
3. אין state גלובלי מוטבל (mutable) מחוץ לשכבת ה-state management (Riverpod). Providers עם scope נכון ו-autoDispose כברירת מחדל.
4. תמונות/קבצים נטענים עם מטמון מוגבל; רשימות ארוכות רק עם builders עצלים (`ListView.builder`).

## 7. סוכנים והאצלה
1. תכנון, פירוק למשימות וביקורת קוד — הסוכן הראשי. מימוש — מואצל לסוכני-משנה.
2. כל משימה לסוכן-משנה כוללת: הפניה ל-`RULES.md`, הקבצים הרלוונטיים, הגדרת תוצר מדויקת, ואיסור לגעת בקבצים מחוץ לתחום המשימה.
3. המפקח בודק כל תוצר: עמידה בכללים, גבולות 500 שורות, טסטים עוברים — לפני commit.

## 8. Git
1. commits קטנים וממוקדים עם הודעה תיאורית באנגלית (`feat:`, `fix:`, `refactor:`, `test:`, `docs:`).
2. אין commit שמשאיר את הפרויקט לא מתקמפל או עם טסטים נכשלים.
3. כללי טסטים ודיפלוי מלאים: `docs/TESTING_AND_DEPLOY.md`.
